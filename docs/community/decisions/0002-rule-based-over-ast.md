# ADR-0002：规则匹配优先于完整 AST

- 状态：accepted
- 日期：2026-09-24
- 决策者：维护者

## 背景

实现 Solidity 静态分析有两条路径：

1. 解析完整 AST（例如基于 `solc --ast` 或 tree-sitter），做数据流/控制流分析；
2. 用轻量语法切片 + 规则模式匹配，快速给出可定位线索。

完整 AST 更准确，但需要编译器二进制、版本管理和更复杂的依赖；课程周期内难以同时保证
准确性、跨平台和零依赖。

## 决策

选择方案 2，但明确它是“高信号线索”而不是“完整证明”。

## 设计约束

- 必须用花括号配对切出函数体，避免规则跨函数误匹配；
- 必须保留原始行号，注释剥离不能改变偏移；
- 每条规则输出置信度；
- 文档必须列出误报边界与已知限制；
- 后续可在 `Scanner` 前增加 AST 适配器，而不改变报告层。

## 结果

- 扫描器能覆盖 7 类常见风险，30 个测试通过；
- 对继承、内联汇编、跨函数重入存在漏报；
- 报告页脚明确“不能替代人工审计”。
